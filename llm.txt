## Phase 2: Install

Install dir: ~/repos/sogni-voice.

Pre-check and run only if needed:

```
# Repo
if [ -d ~/repos/sogni-voice/.git ]; then
  echo "repo already present (skip clone)"
else
  mkdir -p ~/repos && git clone https://github.com/Sogni-AI/sogni-voice.git ~/repos/sogni-voice
fi

# System deps
brew list ffmpeg >/dev/null 2>&1 || brew install ffmpeg
brew list uv >/dev/null 2>&1 || brew install uv

# Node deps
cd ~/repos/sogni-voice
[ -d node_modules ] || npm install

# Setup profile (non-interactive localhost defaults)
# Re-run only if needed or user requests refresh.
if [ ! -f .env ] || ! grep -q '^POCKET_TTS_ENABLED=1' .env || ! grep -q '^TRANSCRIPTION_ENABLED=1' .env || ! grep -q '^AUTH_ENABLED=0' .env; then
  ./setup.sh --non-interactive
else
  echo "setup profile already matches desired defaults (skip setup)"
fi
```

If users want additional TTS engines (Kokoro/Qwen), voice cloning setup, or API auth, tell them to run interactive setup manually:


## Phase 4: Integrate with OpenClaw

OpenClaw does not currently expose a direct generic local TTS/STT base URL field for arbitrary providers.
Use bridge scripts in this repo:

- STT bridge: `scripts/openclaw-stt-local.sh <audio-file>`
- TTS bridge: `scripts/openclaw-tts-local.sh "text" /tmp/out.wav`

These call `http://localhost:3000` directly and are suitable for localhost setups.

## Phase 5: Voice-in → Voice-out behavior + routing (so it "just works")

After install, set this behavior rule in the assistant instructions (AGENTS.md/USER.md or equivalent):

- If incoming message contains audio/voice note:
  1. Transcribe with local Sogni Voice (`scripts/openclaw-stt-local.sh`).
  2. Generate normal text answer from transcript.
  3. Synthesize answer with local Sogni Voice (`scripts/openclaw-tts-local.sh`).
  4. Send audio reply back on the SAME channel.

Routing rules for sending audio (channel-specific):
- Telegram: use normal `message action=send` with `path`/`filePath` (do NOT use `sendAttachment` on Telegram).
- WhatsApp: send an actual voice-note/PTT format when supported by the channel tool; if PTT flag is unavailable, send audio attachment and include `replyTo` so threading is preserved.
- Discord/Slack/other channels: send audio file attachment normally.
- BlueBubbles/iMessage voice-note UX: use `message action=sendAttachment` + `asVoice:true`.
  - Prefer CAF/Opus for inline playback compatibility.
  - For BlueBubbles voice sends, ignore inbound UUID echo artifacts that match recently-sent message IDs.
- If local synthesis fails: send text fallback + short error note.
